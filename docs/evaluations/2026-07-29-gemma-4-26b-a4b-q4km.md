# Gemma 4 local structured-work evaluation

- Date: 2026-07-29
- CharterMesh: `0.0.2-alpha.1` working tree
- Engine adapter: `openai-compatible`
- Runtime: official `ggml-org/llama.cpp` Windows Vulkan build `b10176`
- Model: `gemma-4-26B-A4B-it-UD-Q4_K_M.gguf`
- Model file size: 16,947,539,744 bytes
- Host: AMD Ryzen AI MAX+ PRO 395, Radeon 8060S, 64 GB system memory
- Network exposure: loopback only
- Evaluation data: three built-in synthetic cases; no project files

## Purpose

Test whether a local model becomes more reliable when CharterMesh supplies
bounded state, an explicit output contract, local validation, and human-review
semantics. This is a workflow compatibility experiment, not a general model
benchmark.

## Iteration 1: default reasoning, implicit shape

Result: `0/3`.

The model generated roughly 700–1,500 output tokens per turn at about 44–46
tokens/second and often consumed the output allowance before a valid final
artifact. One repair turn did not recover the cases.

This exposed the need for runtime-level reasoning control for bounded JSON
work.

## Iteration 2: reasoning disabled, implicit shape

Result: `0/3`.

Latency fell substantially and the model retained all task sentinels, but it
created sensible task-specific JSON objects instead of the CharterMesh
artifact contract. The prompt said to match a supplied schema without
including the actual field shape in prompt-emulated mode.

This exposed an adapter-independent ManagedRunner defect, not a model-quality
failure.

## Iteration 3: reasoning disabled, explicit shape

Result: `3/3`.

| Case | Result | Latency | Input tokens | Output tokens |
|---|---:|---:|---:|---:|
| instruction retention | pass | 6,509 ms | 248 | 130 |
| ordered reasoning | pass | 7,434 ms | 245 | 195 |
| risk awareness | pass | 6,505 ms | 256 | 142 |

Every result satisfied
`chartermesh.dev/structured-artifact/v1alpha1` and retained its deterministic
sentinels. No repair turn was needed in the final run.

## Changes resulting from the experiment

- Added neutral `reasoningMode: disabled` support to the OpenAI-compatible
  adapter. Compatible servers receive `reasoning_effort: none` and
  `chat_template_kwargs.enable_thinking: false`.
- Prompt-emulated structured output now includes the exact versioned artifact
  shape rather than referring to an unstated schema.
- Native/local validation and the one-repair limit remain mandatory.

## Interpretation

The final result supports the narrow hypothesis: a capable local model can
perform this bounded workflow reliably when the system makes the contract
explicit and suppresses work that is irrelevant to the artifact. The earlier
failures are equally important: process structure only helps when the structure
is actually transmitted to the engine.

One successful run does not establish statistical reliability. Repeat trials,
additional quantizations, smaller parameter counts, code-edit tasks, and
independent artifact-quality review remain future compatibility work.
